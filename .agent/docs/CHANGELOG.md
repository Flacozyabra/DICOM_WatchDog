## [1.8.3] - 2026-09-22

- **Full EN localization of Monaco Plan Analyzer dialog** — all UI strings (titles, tabs, table headers, verdict cards, status bar, metric labels, error dialogs) now switch between Russian and English based on the active interface language setting.
- **Multi-PC sync: cross-PC folder locking** — implemented `FolderLock` (`.dw_processing.lock`) and SMB retry logic to prevent concurrent file collisions when two PCs share the same network folder.
- **Full patient ID healing** — `process_patient_folder` now validates and heals all files in a study (including CT slices) instead of stopping at the first valid file, preventing partial ID updates.
- **Count RTD/RTP files only when columns are enabled** — `RTDOSE`/`RTPLAN` files are scanned and counted only when the corresponding table columns are active; added `rtd_scanned`/`rtp_scanned` flags.
- **Persistent disk caching (CT + Archive)** — study lists are restored instantly at startup from `%LOCALAPPDATA%\DICOM_WatchDog\*_cache.json`; background workers only re-read folders whose `mtime` changed.

- **Concurrent Multi-PC Folder Locking & Full Patient ID Healing**:
  - Реализован кроссплатформенный механизм взаимной блокировки папок пациентов (`FolderLock` и `.dw_processing.lock`), предотвращающий одновременный конфликт доступа (`PermissionError: [WinError 32]`) при работе нескольких компьютеров через общую сетевую папку (SMB).
  - В фоновом сканировании `FolderScanWorker` добавлена проверка `is_folder_locked(path)`: если папка в данный момент модифицируется другим ПК, читающий воркер отдает данные из кэша (или пропускает обращение к диску), не вызывая файловых блокировок.
  - В `safe_update_patient_ids` реализован механизм повторных попыток (Retry) с экспоненциальной задержкой (до 5 попыток с паузой 0.15–0.75 с) при возникновении временных системных блокировок файлов Windows SMB.
  - В `process_patient_folder` устранена проблема частичного обновления файлов: теперь при включенном `fix_patient_id` процедура валидирует и исправляет все файлы исследования (включая срезы КТ, если их ID рассинхронизирован), быстро сверяя тег `PatientID` без декодирования пикселей (0.05 мс/файл), а не прерывает исправление КТ по первому валидному файлу.
  - Файлы блокировки `.dw_processing.lock` и `.lock` зарегистрированы в `classify_dicom_file` как `IGNORE`, исключая их попадание в расчеты срезов или таблицы.


- **Count RTD and RTP Files Strictly When Columns Are Enabled**:
  - В `core/dicom_utils.py` и `core/archive.py` реализован учет состояния сканирования колонок доз (`RTDOSE`) и планов (`RTPLAN`): файлы сканируются и подсчитываются только тогда, когда соответствующие столбцы включены в таблице.
  - Устранена ошибка, из-за которой сохраненные при выключенных колонках нули блокировали повторный подсчет при включении столбцов; введены флаги `rtd_scanned` и `rtp_scanned`.
  - Исправлена опечатка в ветке `elif not scan_rtp:` (сброс `rtd_val` вместо `rtp_val`).
  - В `load_ct_cache_as_patient_dict` и `load_archive_cache_as_patient_dict` добавлена передача флагов видимости колонок `scan_rtd` и `scan_rtp`.
  - В `ui/main_window.py` добавлен метод `start_archive_scan(force=False, clear_table=True)` и поддержан флаг `clear_table=False` для бесшовного обновления данных без мерцания и сброса строк.
  - В `ui/table_context_menus.py` при включении чекбоксов RTD/RTP в меню заголовка запускается фоновое сканирование с обновлением данных в таблице.

- **Persistent Disk Caching & Instant Startup for CT Images and Archive**:
  - Реализовано персистентное дисковое кэширование метаданных для папок `ct_images` (`%LOCALAPPDATA%\DICOM_WatchDog\ct_images_cache.json`) и `archive` (`archive_cache.json`).
  - При запуске приложения списки исследований из кэша мгновенно отображаются в таблицах «КТ-снимки» и «Архив» (0 мс) до запуска фоновых воркеров, устраняя задержку и пустые экраны с ожиданием сканирования.
  - Оптимизировано фоновое сканирование: папки со стабильным `mtime` не перечитываются через `pydicom`, данные берутся из кэша.
  - В `core/archive.py` и `core/dicom_utils.py` добавлена безопасная сериализация объектов `datetime` в JSON (`isoformat`), устраняющая скрытое падение сохранения кэша.
  - Реализована синхронизация кэшей на диск при операциях архивации, восстановления, удаления, очистки структур и смены ID, а также при закрытии приложения (`closeEvent`).
  - Добавлена очистка устаревших и внешних путей при сохранении кэша и валидация путей в `load_ct_cache_as_patient_dict` / `load_archive_cache_as_patient_dict`.
